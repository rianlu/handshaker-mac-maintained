HandShaker USB 连接与传输测试

按终端提示操作, 完成后回传桌面生成的一份 ZIP.
脚本会等待操作, 由测试者决定何时结束.
以终端显示的测试包编号区分不同测试包. 两端 App 版本由脚本核对, 无需自行搭配版本或手动安装 APK.

开始前

1. 完成其他文件传输. 如旧测试脚本还在运行, 在原窗口按 Ctrl+C, 等它生成日志后再开始新一轮.
2. 解压整个测试包. 保留 APK, platform-tools 和其他文件, 不要只拷贝脚本.
3. 打开 1-安装Mac端.dmg, 将 HandShaker 拖入 Applications 并替换旧版, 暂时不要手动启动.
4. 只保留一台测试手机. 在开发者选项中开启 USB 调试, 保留原来的 USB 用途设置.
5. 双击 2-开始测试.command, 按终端提示连接原来出问题的数据线.

如果运行前已经接线, 直接运行脚本即可. 不用反复手动退出自动打开的 App.
如果 macOS 阻止打开应用或脚本, 在 Finder 中右键选择"打开"; 仍被拦截时查看系统设置中的"隐私与安全性".
同一时间只运行一轮测试. 新脚本检测到另一轮正在运行时会提示回到原窗口.

按这 7 个步骤完成

[1/7] 确认 Mac 诊断版已安装
等待脚本检查版本和签名. 版本不符时, 按提示重新安装包内 DMG.

[2/7] 连接手机, 保存初始信息
连接数据线, 解锁手机并允许这台 Mac 的 USB 调试.
已有调试授权时会自动继续. 未就绪时按终端提示处理, 完成后按回车重新检查.
等待脚本保存旧退出记录, 停止两端 HandShaker 和 Mac 旧后台助手, 再收集系统和 USB 配置.
按手机界面当前显示的 USB 用途选择数字, 不要改动设置. 看不到时选 0.

[3/7] 重新安装 Android 诊断版
查看脚本列出的 HandShaker 副本. 如果存在应用分身或其他手机用户, 一并确认卸载范围.
注意: 卸载会清除列出的 HandShaker 副本的应用数据和授权. 先保存需要保留的应用内数据.
选择确认后, 等待卸载和安装; 手机出现安装确认时允许本次安装.
看到"Android 诊断版安装成功"后继续下一步.
选择保留旧应用时, 脚本会保存现有日志并结束, 不会进行本轮连接测试.

[4/7] 授予权限, 准备正式连接
在手机 HandShaker 中完成以下授权, 返回 App 主界面后按终端提示按回车检查:
- Android 11 及以上: 所有文件访问权限.
- Android 6-10: 存储读写权限.
- Android 6 及以上: 使用期间访问位置; 有精确位置选项时开启.
脚本会核验实际权限状态. 授权未完成时会继续等待操作.
按提示手动拔下手机数据线, 无需按回车. 检测到拔线后, 脚本会自动启动并检查 Mac 诊断版.
此时先不要插回, 等待下一步提示.

[5/7] 正式连接和文件传输
看到插回提示后, 手动插回刚才的数据线, 无需按回车, 等待脚本识别手机.
手机出现 USB 配件访问或电脑信任确认时选择允许. 已授权且没有弹窗时可直接继续.
Mac 显示手机文件后, 在终端输入 1 并按回车, 开始文件测试.
等待 Finder 选中脚本生成的 256 MiB 测试文件.
用 Mac 的 HandShaker 将该文件复制到手机 Download/下载等可写目录.
等待传输显示结果, 再回到终端选择"成功", "失败", "断开/卡死"或"没有完成测试".
如果原问题是间歇性掉线, 继续观察到平时出现问题的时段再选择结果, 不必为了赶时间结束.
速度由文件任务日志自动记录, 无需手工计时. 两个方向的文件任务均可记录, 本轮默认测试 Mac 到手机.

若连接失败, 选择"连接失败或出现异常, 保存现场", 无需反复插拔重测.
需要标记问题时刻时, 输入 M 并按回车.
如果已经手动切换了 USB 用途, 输入 U 并按回车记录当时用途, 然后继续当前阶段.
这些标记是辅助记录, 忘记标记也可以继续回传日志.

[6/7] 确认本轮 USB 操作
回答正式连接和传输期间是否改过 USB 用途, 或额外拔插过数据线.
不要把脚本要求的准备拔插算作额外操作. 记不清时选 0.
仅在反馈连上后断开或传输卡死时, 再记录手机的"仅充电/文件传输"选择框是否出现或被操作. 没有注意时选 0.

[7/7] 收集结果并生成日志包
保持数据线连接, 等待脚本取回两端日志和末尾状态. 对未取得的末尾配置, 持久日志或可检查的事件缺号, 脚本会在调试连接可用时自动补采一次, 然后关闭本轮 App 并生成 ZIP.
仅在调试连接无法恢复时, 按提示再拔插一次以取回手机日志, 无需重新做连接或传输测试.
在 Finder 中找到脚本选中的 ZIP, 完整回传即可.
日志包内的"日志检查.txt"会说明关键缺失项和系统限制. 即使提示部分记录未取得, 也先回传这一份 ZIP, 无需自行重复卸载安装或重做测试.
若显示"本轮提前结束", 回传该 ZIP, 不要将它理解为测试通过.
若压缩失败, 在 Finder 中压缩提示的日志文件夹后回传.

区分手机上的授权和 USB 用途

- USB 调试授权: 允许脚本安装应用和读取诊断信息.
- 文件访问和定位权限: 允许 Android 客户端正常启动和访问文件.
- USB 配件授权: 允许 HandShaker 打开本次 USB 配件通道.
- USB 用途(仅充电, 文件传输等): 保留原设置, 只记录, 不要为测试提前切换.

仅充电也可能正常连接和传文件. MTP 文件传输不是 HandShaker AOA 连接的必要条件.
已连接后切换 USB 用途可能导致重新识别或中断传输; 发生过就如实记录.

中途结束和测试后

在交互提示处输入 Q 并按回车, 或在任意阶段按一次 Ctrl+C, 等待脚本保存日志并打包.
尽量不要直接关闭终端窗口. 部分日志未取得或测试未完成时, 仍回传已生成的 ZIP.
如提示部分 App 未能关闭, 先拔下数据线. 需要恢复使用时, 从 Applications 重新打开 HandShaker.
256 MiB 测试文件由脚本在 Mac 本地生成, 不在安装包或日志 ZIP 中. 测试后可手动删除手机中的测试文件和终端提示的 Mac 测试文件目录.

需要查看记录时, 先打开 ZIP 内的"日志检查.txt". 详细诊断内容位于 usb 文件夹:
- diagnosis-summary.txt: 流程结果和缺失项.
- usb-configuration-summary.txt: 初始用途, 请求/实际 USB 配置, 配件授权和切换记录.
- transfer-summary.txt / file-transfers.tsv: 实际传输通道, 文件字节, 耗时和平均 MiB/s.
- capture-coverage.tsv / android-event-sequence.tsv: 各项采集状态和已捕获手机事件范围内的缺号检查.

平均速度只在任务成功, 字节数一致且计时有效时显示. 未取得的指标标为未知.
日志检查通过表示关键记录已取得, 不代表其他手机的故障已修复. 原问题本轮没有出现时, 记录只能说明本轮表现.
物理插拔, 手机安装确认和授权由测试者操作, 脚本不会用软件切换 USB 模式代替拔插.
